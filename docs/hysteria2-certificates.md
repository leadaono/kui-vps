# Hysteria2 self-signed certificates in subscriptions

KUI Agents generate a **different self-signed leaf certificate for each node**. The certificate fingerprint of one VPS must never be copied to another VPS. The Agent now reads only its own public `cert_<node-id>.pem`, hashes the DER leaf with SHA-256, and sends the 64-hex-character digest to the panel in its authenticated status report. It never sends a private key. The panel verifies that the reporting Agent owns the target VPS and node ID, then includes `pinSHA256=<live digest>` in the Hysteria2 URI instead of the old `insecure=1`-only URI. Refresh the subscription after certificate renewal/replacement; old client pins are not automatically updated without re-importing/updating.

**Upgrade both panel and Agent.** The panel omits its own Hysteria2 URI if the Agent has not reported a valid certificate hash in the last two hours, or the certificate is unavailable. Check Agent health and wait for a fresh report rather than restoring `insecure=1`. This does not affect third-party imported subscriptions, which cannot be attested by our Agent. Existing imported client profiles are unchanged until their subscription is refreshed.

**Client compatibility is not universal.** This URI deliberately omits `insecure=1`: native Hysteria2 clients that require both `insecure: true` and `pinSHA256` for self-signed certificates may reject it. Do not add `insecure=1` to a shared URI merely to support older clients that might ignore the pin and silently disable validation. v2rayN with an Xray core that supports `pinnedPeerCertSha256` can import the URI and verify the certificate fingerprint; confirm the saved pin and test the node. Other Hysteria2 clients can interpret `pinSHA256` and self-signed certificate verification differently. For v2rayN with sing-box core, import the **same node's current public PEM** into its certificate-chain field and do not skip verification. Do not install this PEM into the Windows global trust store. This PR does not embed PEM into share links or claim to automatically configure sing-box/Mihomo/Clash. The pre-existing Clash YAML path still sets `skip-cert-verify: true`; it is unchanged for compatibility and is **not** protected by this pin. Do not interpret a successful Clash import as certificate verification. Never treat a `-1` latency alone as proof of a certificate error: inspect the first client-core error as well as UDP reachability and authentication.

For a KUI-generated node, the certificate is `/opt/kui/cert_<node-id>.pem` on its **own** VPS. Verify that it is a public certificate before copying it to your client. A certificate change rotates the SHA-256 and requires a subscription refresh (or a fresh PEM import for sing-box). No pin in this repository is a universal default.
